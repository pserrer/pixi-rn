## Install

```sh
npm install pixi-rn pixi.js expo-gl expo-asset
```

`pixi.js`, `expo-gl` and `expo-asset` are peer dependencies — pixi-rn doesn't
pin their versions for you, since your app already does.

## A minimal screen

Everything below lives inside `GLView`'s `onContextCreate` — the one place
you have a live GL context to build a renderer against.

```tsx
import { StyleSheet } from 'react-native';
import { GLView, type ExpoWebGLRenderingContext } from 'expo-gl';
import { Container } from 'pixi.js';
import { createRenderer, makeWhiteTexture, startFrameLoop, UiRect } from 'pixi-rn';

const W = 390;
const H = 844;

async function onContextCreate(gl: ExpoWebGLRenderingContext) {
  // 1. The renderer — handles the WebGL1-vs-2 trap, the parked tickers, and
  //    the `getParameter` guard for you. See "Concepts › Rendering".
  const renderer = await createRenderer(gl, { width: W, height: H });

  // 2. A scene. `Graphics` isn't available here (see the Introduction) — a
  //    solid fill is a tinted 1×1 texture instead.
  const stage = new Container();
  const white = makeWhiteTexture();
  const square = new UiRect(white, { x: W / 2 - 40, y: H / 2 - 40, width: 80, height: 80, color: 0xffd700 });
  stage.addChild(square);

  // 3. ONE frame loop drives everything — sim (if you have one), scene
  //    mutation, and the render call. See "Concepts › Rendering".
  startFrameLoop({
    gl,
    onFrame: (now, dtMs) => {
      square.rotation += dtMs * 0.001;
      renderer.render({ container: stage });
    },
    onError: (error, stage) => console.error(`pixi-rn: ${stage}`, error),
  });
}

export function Screen() {
  return <GLView style={StyleSheet.absoluteFill} onContextCreate={onContextCreate} />;
}
```

That's a renderer, a shape, and a loop — nothing else is required to get
pixels moving. Everything past this point (layout, text, buttons, screens) is
built the same way: retained pixi nodes, mutated from that one loop.
